中危CVSS 6.5CWE-307 vuln-login-no-ratelimit

登录接口无速率限制，可账户爆破 已黑盒复现

POST /api/v1/login · shop.acme-demo.example
主因无限流中间件；失败计数只在前端。
机制连打恒返 401，无 429 / 验证码 / 锁定。
加重注册报错泄露用户名是否存在，可枚举。
建模限流被当成前端体验，而非服务端边界。
任何拿到用户名的人，都能不限次数地猜这个账号的密码。
失败不计数、不锁定，用户名又可枚举——字典可直接跑。
复现（受控速率，未爆破）：
bash
# 同一账号连打 100 次错误密码，观察是否出现限流
for i in $(seq 100); do
  curl -s -o /dev/null -w "%{http_code} " \
    -X POST https://shop.acme-demo.example/api/v1/login \
    -d "user=demo@acme.example&pass=wrong-$i"
done
实测：100 次全是 401，没有一次 429 / 锁定。
Request
POST /api/v1/login HTTP/1.1
Host: shop.acme-demo.example
Content-Type: application/x-www-form-urlencoded

user=demo@acme.example&pass=wrong-99
Response
HTTP/1.1 401 Unauthorized
Content-Type: application/json

{"error":"invalid_credentials"}

风险：账户接管、撞库放大；用户量大的站点尤其危险。

修复建议
  1. 服务端限流：IP+账号双维度，失败退避 / 429。
  2. 账户锁定 / 验证码：连续失败即触发。
  3. 统一报错，堵用户名枚举。
  4. 登录异常告警。

整段可复制脚本：
bash
#!/usr/bin/env bash
# tke security · 复现：登录接口速率限制探测（只读、受控）
set -euo pipefail
URL="https://shop.acme-demo.example/api/v1/login"
codes=$(for i in $(seq 1 100); do
  curl -s -o /dev/null -w "%{http_code}\n" -X POST "$URL" \
    -d "user=demo@acme.example&pass=wrong-$i"
done | sort | uniq -c)
echo "$codes"
if echo "$codes" | grep -q " 429"; then
  echo "PASS：出现 429，存在限流"
else
  echo "FAIL：100 次内无 429 / 无锁定 —— 无速率限制"
fi
预期：有漏洞打 FAIL，修好打 PASS。
