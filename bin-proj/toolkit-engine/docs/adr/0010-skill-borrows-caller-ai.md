# ADR-0010: skill 模式借调用方的 AI——tke 退回成设备操作原语

- **状态**: 生效（2026-08-12 用户拍板）
- **日期**: 2026-08-12
- **关联**: **取代 ADR-0009 的 `tke task`**；INV-3 / INV-6 / INV-11；ADR-0002（tke 自带 AI 的 REPL 形态,保留）
- **关联文档**: `../skill-integration.md`

## 背景

ADR-0009 为「外部 agent 调用 tke」设计了 headless 一次性模式：五态出口、决策点结构化回传。
它整套复杂度都在解决一个问题——**一个 agent 怎么远程遥控另一个 agent**。

但在真实场景里（Claude Code 写完功能要验），**调用方自己就是 AI**：
它有上下文（刚写的代码、testid、期望行为）、有推理能力、用户已经为它付过费。
再让它去驱动 tke 内嵌的另一个 AI，是白白多一层：多配一份 API key、多一层不确定性、
多一套决策回传协议。

## 决策

**skill 模式下不用 tke 的内置 AI。** Claude Code 直接调 tke 的原子命令
（`fetch` / `refresh` / `control *` / `element add` / `steps` / `run`）完成探索，
探索策略与结束条件由 skill 的提示词约束；tke 退回成**干净的设备操作原语 + 证据产出器**。

产物与 harness 一致：`foo.tks` + `foo.tklib` 两件套，外加 `tke run --log` 的
标注截图序列（横幅+元素框+点击点+滑动轨迹）与 `log.json`。

**`tke task`（ADR-0009）不做了**——它的存在前提（外部 agent 想调用 tke 的 AI）已消失。
ADR-0009 中「决策点属于与用户对话的层」的判断仍然成立，只是实现方式变了：
决策本来就发生在 Claude Code 那一侧，不需要跨进程回传。

**`tke harness` 的内置 AI 保留**（ADR-0002 不变）：Electron App 用户、
没有 coding agent 的纯 CLI 用户仍然需要它。两条路并存,不是替换。

## 理由与代价

**收益（按重要性）：**
1. **消除 agent 套 agent**——ADR-0009 的整层复杂度消失。
2. **结束条件变硬**：从「supervisor(LLM) 判定达成」变成「`tke run` 回放跑通」。
   回放器真实执行断言步,这是硬证据,比原来的软证据更可信。
3. **导入即用**：不需要配 `[ai]`、不需要第二份 token。

**代价（必须正视）：**
- **质量护栏会退化**。harness 里的 asserter（每次导航踩实）、supervisor（finish 把关）、
  页面契约投票（INV-6）是几十版换来的。**提示词管不住"每一步都记得踩实"**——
  它会随调用方 AI 的注意力漂移。第一版接受这个退化,用最后的 `tke run` 回放兜底;
  **若实测脚本质量不可用,出路是把护栏做成必须调用的 tke 子命令,而不是把提示词写得更长**。
  这也是本 ADR 的重新审视触发条件。
- **`--copilot` 定位自愈失效**（它需要 `[ai]`）。回放失败会直接报错——但这正确:
  失败报给调用方 AI 判断,与「AI 外包给调用方」一致。skill 里要写明这个预期。
- **token 成本落在调用方**。主循环必须用 `fetch --interactive` 的文本元素表,
  不能每步截图读图（explorer 早就是这么设计的,这份智慧要继承）。
