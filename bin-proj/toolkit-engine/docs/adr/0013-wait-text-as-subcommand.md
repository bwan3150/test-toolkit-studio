# ADR-0013 「等文字出现」做成子命令，而不是写进提示词

- 日期：2026-08-15
- 状态：已落地（web 本机实测；跨设备真机待验）
- 关联：ADR-0010（skill 借调用方 AI）、Q-8、Q-9、INV-9（失败必须可见）

## 背景

`tke-ui-test` skill 不建元素库（ADR-0010），所以 `.tks` 的重试断言
`断言 [{元素}, 存在, 15s]` 用不了——它需要元素库。于是"等后端异步下发 / 跨设备同步"
只能让调用方 AI 自己写 shell 轮询，护栏全在 SKILL.md 的措辞里：

```bash
found=0
for i in $(seq 1 15); do tke -d X fetch | grep -q "名字" && { found=1; break; }; sleep 2; done
[ "$found" = 1 ] && echo 出现了 || echo 没出现
```

这段有三个坑，每个都会产生**假结论**（不是跑不起来，是跑起来了、结论是错的）：

1. 忘超时 → 挂死
2. 忘判命中 → "循环跑完"被当成"通过"（C-3）
3. 误加 `--interactive` → 纯文本标签被过滤掉，等到超时报假失败（C-1）

第 3 个坑是**写 SKILL.md 的我自己第一版就踩的**。

## 决策

加 `tke -d <设备> fetch --wait-text <文本> [--timeout <秒>]`：

- 轮询采集（500ms 一轮），**命中即刻返回**，正常输出元素表、退出码 0
- 超时 → 报错到 stderr、**非零退出**，`||` 与 `$LASTEXITCODE` 天然接得住
- 查**全量**元素（不受 `--interactive` 影响），多候选 `"A|B"` 任一命中即算
- 匹配口径与 `滚动查找` 共用 `utils::scroll`（空格/大小写不敏感），不再多一套语义

SKILL.md / pitfalls.md / steps-syntax.md / tke-commands.md 里的手写轮询范例**全部替换**。

## 理由

ADR-0010 的"埋的坑"那节已经写过结论，这次只是照它执行：

> 护栏退化的出路是**把护栏做成必须调用的子命令**，不是把提示词写更长。

Q-9 这场实测又给了一个独立佐证：`滚动查找` 的能力**早就存在且不需要元素库**，
但 `steps-syntax.md` 把它标成"需要元素库"，于是调用方 AI 一次都没用过——
**靠文档传递能力是脆的，靠退出码传递结论是硬的**。同理，与其反复叮嘱
"记得判命中"，不如让"没等到"在 shell 层面根本没法被当成"等到了"。

## 代价 / 边界

- 它只解决"等文字出现"。"等文字消失"（loading 结束）没做——目前没有实证需求，
  真需要时再加 `--wait-gone`，别现在就设计。
- 与视口限制叠加：文字在**视口外**时 `--wait-text` 也等不到（采集只收视口内元素）。
  超时报错里已写明这一点并指向 `滚动查找`。
- 轮询期间不产证据（不落 `--log`）。它是"等"，不是"操作"；证据由前后的 `steps` 留。
