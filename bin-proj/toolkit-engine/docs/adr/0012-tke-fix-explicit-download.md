# ADR-0012：依赖补齐只在 `tke fix` 里发生，普通命令绝不自动下载

- 状态：生效（用户拍板 2026-08-13）
- 关联：ADR-0010（skill 借调用方 AI）、INV-9（失败必须可见）、P-19（分发源的两个坑）

## 背景

tke 光有二进制跑不起来：网页要 chromedriver + Chrome for Testing，安卓要 adb，
iOS 要 go-ios。使用者第一次用（尤其是从 skill 装进来的）经常缺一两样，而当时的报错
指不到点上：

| 场景 | 当时报什么 |
|---|---|
| 安卓缺 adb | 「adb 可执行文件缺失…请放在与 tke 相同目录」✅ |
| web 缺 chromedriver（启动时） | 「chromedriver 可执行文件缺失…」✅ |
| web 缺 chromedriver（先 fetch） | 「无活动浏览器会话，请先执行 启动」❌ 指错方向 |
| **web 缺 Chrome** | 「session not created (日志: …)」❌❌ 完全看不出缺什么 |

后两条会让人（和 AI）在错误的方向上折腾很久。

## 决策

**一、加一条显式命令 `tke fix`**，它是**唯一会联网下载的命令**。

```
tke fix                      # 按平台补齐所有缺的，下载前问一句
tke fix -y --profile web     # 不问直接下，只补网页那套
tke fix --check              # 只报告缺什么，不下载；缺东西时退出码非 0（CI 用）
```

**二、普通命令（run/steps/fetch/harness…）缺依赖时只报错并指路，绝不自己下载。**

考虑过"发现缺就自动拉取"，否掉了。一条 CLI 命令突然静默拖 600MB，在内网、离线、
CI、按流量计费的机器上都是灾难，企业环境还有合规问题。**要不要下、什么时候下，
是使用者的决定**——报错里把 `tke fix --profile web` 给出来就够了。

## 实现上几个不显然的选择

**下载走 `curl` 子进程，不用 Rust HTTP 客户端。** reqwest 在本项目是 `ocr-online`
的可选依赖，CI 的 `--no-default-features` 构建里根本没有，而 `tke fix` 必须在任何
构建下都能用。tke 本来就是"调外部工具"的架构（adb/chromedriver/go-ios 都是子进程），
install.sh 也依赖 curl，环境要求一致。

**每个文件都验文件头。** 分发平台对不存在的路径回落 200 + 一段 HTML（SPA 兜底），
curl 的 `-f` 完全拦不住——不验就会把网页当二进制装进去（P-19）。

**用 VERSION 里的 build 戳当下载缓存键。** Cloudflare 缓存 4h 且不认 no-cache 请求头，
只有变化的查询参数能破缓存（P-19）。

**装没装的判据是「可执行文件在不在」，不是「目录在不在」。** 这条是被自己咬出来的：
第一版 Chrome 解压因为 zip 特性没开而失败，但半个解压出来的目录留在那儿，复验看到
目录存在就报「✅ 补齐了」并退出码 0——**一个我一路在防的假成功，自己犯了**。
现在判据落到二进制本身，且解压失败会清掉半成品目录。

**Chrome 的路径定义（`CHROME_REL`）驱动层与 fix 共用一份。** 各写一套的话会出这种
怪事：fix 说装好了，驱动却找不到。

## 后果

- 使用者第一次用撞到缺依赖时，一句话就能自救；CI 可以用 `--check` 提前判断环境
- tke 二进制多了一条网络路径，但只在显式调用时走
- 分发源的可用性成了 `tke fix` 的前提；换自建源用 `--base-url` 或 `TKE_BASE_URL`
- 没覆盖：`tke fix` **不升级 tke 自己**（自我替换正在运行的二进制另有一堆坑），
  要更新 tke 仍走 `install.sh`

> 并把版本新鲜度检查从「比 tke 版本号」换成「比 build 戳」——见 **ADR-0014**。

> **2026-08-17 再补**：新增的 `tke update` 也会下载——但它**是用户显式
> 打出来的命令**，等价于手动跑那条 curl，与本 ADR「不偷偷下载」的精神一致。
> 仍然没有任何**普通命令**（run/steps/fetch…）会自己联网取依赖。
