# ADR-0014 `tke fix` 更名 `tke doctor`，并把「本地是不是旧版」变成看得见的一行

- 日期：2026-08-17
- 状态：已落地（本机实测；跨平台待验）
- 关联：ADR-0012（fix 是唯一联网下载的命令）、Q-11、INV-9（失败必须可见）

## 背景

Q-11 记的那个缺口，代价已经付过一次了：用户机器上装好的 skill **装完就不动**，
没有任何东西会告诉他有新版。一次会话改了 SKILL.md 的四个修复，用户重跑时拿到的仍是
两天前的旧文档——**必然得出"没改善"的结论，而我们会以为是修复无效**。

已有的 `tke fix --check` 其实一直在联网比版本，但它只比 **tke 二进制的版本号**：

- 版本号（`0.7.4-beta`）**只在 bump 时才变**，而 SKILL.md 天天改；
- 只改 skill 文档的发布根本不会让它变 → 体检照样报"与分发源一致"。

这次撞坑的现场正是如此：tke 是刚编的、skill 是两天前的，`--check` 说一切正常。

另一个问题是名字：`fix` 干的其实是体检的活（依赖 / 设备 / 版本 / 落点 / 有头无头），
"fix" 让人以为它只会"修"，想不到用它查环境。

## 决策

**① 更名 + 默认行为翻转**

| 命令 | 行为 |
|---|---|
| `tke doctor` | 体检，**不下载任何东西** |
| `tke doctor --fix` | 体检 + 补齐缺的依赖（会联网下载） |
| `tke fix` | **别名**，等同 `doctor --fix`（保持旧语义：默认就下载） |
| `tke fix --check` | **别名**，等同 `doctor` |

别名不是过渡措施而是长期保留：已发布的 `install.sh`、用户脚本、以及**用户机器上那份
旧 SKILL.md** 里全是 `tke fix --check`——它们不会因为我们改名就自己更新（这正是本 ADR
要解决的那个问题，不能自己再犯一遍）。

**② 比 `build` 戳，不比版本号**

分发源 VERSION 里的 `build: 20260815-040547` **每次发布都变**。
`publish.sh` 把这份 VERSION **一起打进 skill 包**，装完就躺在 skill 目录里，
于是"本地这份 skill 是哪一批"变得有据可查。

**③ 只提醒，不代劳**

发现不一致只打印一行 + 更新命令，**绝不自己覆盖二进制**：
覆盖正在运行的可执行文件在三个平台各有各的坑（Windows 锁文件 / Linux ETXTBSY /
macOS 签名失配），`install.sh` 已经把这些踩平并验证过，没必要在 Rust 里重踩一遍。

> **2026-08-17 补充：加了 `tke update` / `tke uninstall`**（用户："是不是应该有个
> tke update 和 tke uninstall 来自己调用卸载和升级？"）。
>
> **决策没变**：仍然不自动更新，只是把那串 curl URL 收进一条命令——**用户显式打了
> `tke update` 才会发生**。实现上也没有另起一套逻辑：**就是去跑官方的 install.sh /
> uninstall.sh**，在 Rust 里重写一遍只会多一条必然分叉的路径。
>
> 关键实现（用户原话："执行这个 curl 指令然后立刻放手，让 sh 脚本来替换自己"）：
> **Unix 用 `exec` 把本进程替换掉**。tke 就此消失、bash 接管同一个 PID 与前台——
> 输出/Ctrl+C/退出码全部照常（不是后台任务那种输出乱飞），而且**没有任何进程还占着
> tke 的可执行文件**，脚本可以随便覆盖。Windows 没有 exec 语义，只能 spawn 等待，
> 所以 `install.ps1` 里备了"删不掉就改名"的兜底（Windows 允许重命名运行中的文件）。
>
> 安全：**不用 `curl … | bash`**。分发平台对不存在的路径回落 200 + HTML（P-19），
> 管道执行会把网页喂给 bash。先落地、验文件头（`#!` / `<#`），再执行。

**④ 挂在 `steps` 上 + 缓存 4 小时**

指望人或 AI 想起来跑体检，正是上次踩坑的原因。`tke steps` 是调用方 AI **每次操作设备
都会走**的命令，是唯一能保证被看见的位置。三条克制：结果缓存 4 小时（每批都问，
每 4 小时才真联网一次，超时 5s）、打到 **stderr**（stdout 是给 Electron 解析的 NDJSON）、
`--json` 时闭嘴。

## 与 ADR-0012 的边界

ADR-0012 说"下载只在 `tke fix` 里发生"。**这条没有变**：
新增的检查只 `curl` 一个几十字节的 VERSION，不下载任何依赖，也不写除缓存戳以外的东西。
"不偷偷拖几百 MB"这个承诺完好——被禁止的是**未经同意的大体积下载**，不是一切网络访问
（`fix --check` 本来就在联网比版本，这次只是把比的东西换准了）。

## 代价 / 边界

- **skill 目录靠猜**：只看 `$PWD/.claude/skills/tke-ui-test` 与 `~/.claude/skills/...` 两处。
  装到别处（或换了 AI 客户端）就查不到 → 报"未安装"，不误报过期。
- **老安装器装的 skill 没有 VERSION 文件** → 报"装了，但没有版本信息"，**不当成过期**。
  无从判断时宁可漏报：误报会让人学会忽略这行提醒，那比不报更糟。
- 本地自己编的 tke（`BUILD_VERSION=unknown`）不参与版本比对，否则开发时天天报不一致。
- 提醒措辞是"**不一致**"而不是"该更新了"：本地可能是刚编出来的、比分发源还新。
