# ADR-0009: headless 一次性任务模式——把"对话层"外包给调用方 agent

- **状态**: 生效（2026-08-12 用户拍板；**契约已定，实现未开始**）
- **日期**: 2026-08-12（提案 → 同日拍板，命名定为 `tke task`）
- **关联**: INV-3 / INV-9 / INV-12, ADR-0002（REPL 形态）, ADR-0006（run 语义分界）, PITFALLS P-10
- **驱动场景**: 把 tke 做成 Claude Code 等 coding agent 可调用的 skill（见 `../skill-integration.md`）

## 背景

tke 现在有三个前端（TUI / Plain / Json），但**没有一个是"非交互一次性"**：

- `tke harness` 是对话式 REPL（ADR-0002）。管道/CI 下落到 `PlainFrontend`，
  而 `PlainFrontend::supports_prompts()` 取默认值 `false`、`await_answer` 却仍走
  `read_user_line` 阻塞读 stdin——想提问时的行为是"悬着或读到空串",**不是契约,是未定义行为**。
- `--json`（`JsonFrontend`）是双向 NDJSON,为 Electron app 长连接设计,要求调用方实现一个
  事件循环并负责回话。让另一个 agent 去实现它,等于 agent 套 agent。
- `tke run` 反倒天生合规:输入路径、输出 NDJSON、退出码 0/1（ADR-0006）——但它只回放,不探索。

于是外部 agent 想用 tke 只有两条路:要么驱动一个 REPL（贵、不确定、无终止条件）,
要么只能用回放（覆盖不了"还没有脚本"的场景）。

## 决策

新增**第四种形态:headless 一次性任务模式**,命名 **`tke task`**（用户拍板;与 `harness`
并列的顶层命令,而非 `harness --headless` 的旗标——两者的出口语义与 `ask_user` 行为不同,
做成同一命令的旗标会让"这次调用到底会不会阻塞问人"取决于一个 flag,顶层命令更诚实）。
共用 orchestrator 与全部工具,只换外壳。契约四条:

1. **一次性**:读任务输入 → 跑 → 写结构化报告 → 退出。无 REPL,无常驻。
2. **五态出口**,写进报告 `outcome` 并映射退出码:
   `passed`(0) / `failed`(1) / `needs_decision`(2) / `blocked`(3) / `error`(4)。
3. **决策点不静默降级,结构化回传**。headless 下 `ask_user` 不再阻塞读 stdin,而是
   **立刻终止本次运行**,以 `outcome: needs_decision` + 问题/选项/上下文/现场快照落进报告。
   调用方（Claude Code）自行决定或升给用户,再带着答案发起下一次调用。
4. **证据分级**:报告中「回放通过」(回放器真实执行断言步,硬证据) 与
   「AI 判定达成」(supervisor/页面契约投票,软证据) **必须分字段**,禁止合并成单个 success。

## 理由与代价

**为什么这不违反 INV-3。** INV-3 要的是"修复决策留在与用户对话的层",不是"必须是 tke 自己的 REPL"。
在 skill 场景里,与用户对话的那一层就是调用方 agent。决策点回传 = 把对话层外包出去,
而不是让 tke 自作主张——真正违反 INV-3 的是"headless 下让 tke 自己猜着办"。
反过来说:**headless 模式一旦开始自行决策,这条 ADR 就失效了**,这是重新审视的触发条件。

**为什么不直接上 MCP。** MCP 能做中途双向交互,但要求常驻会话与更重的集成。
当前场景（改完代码验一次功能）是天然一次性的,CLI + 报告文件足够,且能被 CI 直接复用。
**何时该转 MCP**:当"回传决策点 → 重新发起调用"的往返成本明显高于收益时(例如一次任务要往返 5 次以上)。

**为什么不复用 `--json`。** 那是长连接协议,面向已实现事件循环的宿主(app)。
让每个想用 tke 的 agent 都去实现它,是把集成成本乘以调用方数量。

**代价与风险:**
- 多一条执行路径要维护;`ask_user` 在两种外壳下语义不同(REPL=问人 / headless=终止回传),
  是新的认知负担,必须在工具描述与代码注释里写死。
- 探索类任务本身是分钟级、几万 token 的,一次性模式不会改变这个成本,只是让它可被脚本编排。
  调用方必须预算(`budget` 字段)与超时。
- 并发调用会撞 P-10(同秒共享工作区互相覆盖):headless 模式**必须**要求每次调用传独立
  `--cache` / `--current-dir`,或自行按调用生成隔离目录。
- INV-12 不变:登录态等前提仍是"查得出、说得清、不代办",headless 下表现为 `outcome: blocked`
  + 明确的前提说明,而不是尝试自动登录。
- INV-9 不变:被环境跳过的增强、失败的质量闸门,在报告里必须有对应字段,不许静默。
