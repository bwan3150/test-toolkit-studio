# ADR-0015 浏览器默认无头；凭据默认不经手，经手也不落进证据

- 日期：2026-08-17
- 状态：已落地（本机 web 实测；移动端密码框待真机验）
- 关联：ADR-0010（skill 借调用方 AI）、INV-9（失败必须可见）、C-6/C-7/C-18

## 背景

用户提的原话：**"能否默认跑无头浏览器，有问题再换有头，因为有头的浏览器操作起来会和用户抢鼠标。"**

确实：自动化一跑就弹窗口、抢焦点，人没法一边跑检查一边干别的。而无头与有头的渲染
**早已验证一致**（同为 1280×813，bounds 零差异），日常检查没有任何理由把窗口弹出来。

但直接把默认翻过来会打断一条既有流程：SKILL.md 教的是"平台要登录就**停下来让用户在那个
浏览器窗口里自己登**"——无头就没窗口了。顺着这个问题，用户提出分层策略：
AI 问用户要信息并代填，用户不愿意暴露凭据时再切有头。

## 决策

**① 默认无头**

`HeadlessMode::Auto.resolve()` 从"按桌面环境探测"改为**恒定无头**。要看着它跑用 `--headless=off`。

**② Auto 不再参与"会话模式失配"判断**

这是让登录流程还能走通的关键。会话跨命令复用，而模式失配会**销毁会话**（P-18 的修复）。
若 Auto 仍被当成"要求无头"，那么：

```
--headless=off 开窗口 → 用户手动登录 → 下一条命令不带参数(Auto=无头) → 失配 → 销毁 → 登录态没了
```

所以新增 `HeadlessMode::explicit() -> Option<bool>`：Auto 返回 `None` = **"不挑，现有会话
什么样就什么样"**，只有显式 `on/off` 才要求匹配。于是"开一次窗口，后续照常跑"成立。

**③ 凭据：两条路都支持，默认走"用户自己登"**

- 默认：切有头，停下来等用户自己输。凭据不进 AI 上下文、不进证据、不进任何日志。
- 用户主动给凭据时才代填（他明说"密码是 x，你来填"）。

**④ "证据里不出现密码"做成硬能力，而不是嘱咐 AI**

实测证据（本会话真跑过）：`输入 ["密码", "hunter2"]` 会让明文出现在**三处**——
`log.json`、`report.html`、**以及标注截图的顶部横幅（烧进像素）**。
而报告正是拿去分享的东西（这个会话里就把报告传到过公网 URL）。

所以：

| 层 | 做法 |
|---|---|
| 采集 | 密码框**永远不取 value**（web `type=password`），元素表里只显示 `••••••` |
| 元素模型 | `UIElement::is_password`——与安卓 uiautomator 原生的 `password="true"` 同名对齐，三平台一条路 |
| 判据 | **焦点所在元素**的 type（web 由 `input_text` 回报）。按"解析出的坐标上有什么"会漏：`输入 ["密码", …]` 常命中 `<label>`，点它同样能聚焦到密码框（实测撞过） |
| 落盘 | 命令原文经 `utils::redact` 打码后才进 log / 报告 / 截图横幅 |

**打码的失败方向必须是安全的**：任何不符合预期的命令结构一律**整条打掉**，
绝不"原样退回"。这条是从一次真实的测试失败里来的——`输入 ["密码, "hunter2]`（值没闭合）
引号数恰好是偶数，"只替换最后一对"把明文留在了外面。**少打一次码就是泄一次密码。**

## 代价 / 边界

- **移动端的密码框判据较弱**：adb/wda 没有"焦点元素"这个概念，只能靠页面结构里的
  `password="true"`（安卓原生有，iOS 的 WDA 未验）。web 是完整的。
- 打码只保护**证据**，保护不了 **AI 的上下文和会话记录**——所以默认仍是"别经手"。
- `desktop_available()` 保留，但只用于体检时说明"这台机能不能开窗口"，不再决定默认值。
- 有头模式下人手动输入的密码，浏览器不会把它交给采集层（value 不取），所以同样不落证据。
