## 这一场的实质

**几乎所有工作量花在「实跑逼出来的洞」上，不在写新功能。** 新功能只有两件
（反向通道 ADR-0024、多台模拟器），其余全是修 —— 而每一个都是**跑起来之前
看不出来的**：编译过、单测绿、代码读着也对。

值得下一场记住的模式：

| 洞 | 为什么之前发现不了 |
|---|---|
| 缺 `步骤:` 的脚本零步跑完报成功 | 判据 `成功数==总数` 在 0/0 时恒真 |
| 平台选了 web、节点去租 android | 错误信息如实描述了它做的事，只是没说"我为什么找 android" |
| 缺 AI 配置被判成"用例没通过" | done.success=false 一律 failed，错误播报被丢 |
| 写进去了读回来没有 | 迁移和写入都做了，**读取路径没人动** |
| 连 https 平台 panic | 本地一路测 http，**验证时用的协议跟真实用法不一样** |
| 第二台 AVD 建了认不出 | 参数化漏了一处；而"已装"的判据只看文件在不在 |
| 设备池启动扫一次就定死 | `set_pool` 这个函数在，但**没有任何地方调用它** |

## 硬规矩（新增）

**INV-18 CLI 输出不解释自己**：终端每一行要么是结果、要么是下一步能敲的命令。
判据是「这句话会不会改变他下一步做什么」。需要解释的写进 `docs/`。
错误信息不受限——它必须说清为什么失败、怎么办。

## 2026-08-28 补记（本机模拟器实测）

**逼出来的三刀**（commit 81685f9b / 3e105849）：

1. **P-62 采集失败被说成「应用没启动」**。`not_ready` 只有两种分支，
   任何采集失败都归进 `need_launch`，提示词跟着催 launch，而**真正的错误原文
   一个字都没给 AI**。实测代价：十几轮原地读截图、每轮 5.7 万 token。
   现在三分（`not_ready_kind`），并把设备说的原话带给 AI。
2. **JSON 前端 `free_input` 写死 false**，前端照着它禁掉输入框；带选项时还走默认实现，
   选项被拼进问题文字、`options` 是空的。现在如实发。
3. **`remote status` 的 `version_match` 恒假**（节点报"版本号 (构建号)"，本地只比版本号）。

**还没做的**：

- 平台释放后节点仍持租约 → 409 直到 TTL（**Q-15，本场又撞上一次**，只能重启节点绕开）
- 节点被 kill 时 harness 子进程成孤儿（本场清掉 3 个），release 路径是否会留孤儿未验
- `uiautomator dump` 在部分页面**连超时都不报**，只回空输出，
  错误文案退化成「没有输出」——原因还在设备侧，tke 这边只是转述

## 2026-08-28 补记（云设备体验走查）

两刀，都是"不报错所以一直被当成别的问题"：

- **P-63 同一台设备并发两条命令 → 静默回空表**（并发 353 字节 vs 串行 3824，
  exit 0）。serve 加了会话闸 `LeaseTable::gate`：一个租约一次只跑一条命令，
  只管命令层（exec/screen），不圈 L2 的 harness（否则任务跑着时连截图都被堵）。
- **P-64 `fetch --interactive` 的元素一半没名字**（安卓的行是「可点容器 +
  里面的 TextView」）。新增 `UIElement.child_text`，沿 parent_index 往下取，
  不覆盖 `text`。踩到的坑：先改的 `filter_interactive_elements` **没有任何调用方**，
  真正在跑的是 fetch.rs 里内联的两份 —— 改 pub fn 之前先 grep 谁在调它。

## 2026-08-28 源码沙盒定稿（ADR-0025，只写了文档）

用户提出：有些项目拿得到源码，能不能在节点上开项目沙盒、选待测分支，
让 harness 据此测得更准更快。**这一场只定稿，没动代码**（用户拍板）。

要点（细节在 ADR-0025 / INV-19）：

- 拆成两件事：源码当**图纸**（做）vs 当**被测对象**（不做，那是重造 CI）。
  待测包由已有 CI 产出，tke 只负责拿来装上测。
- **INV-19 是这件事的成败所在**：源码只回答"怎么找、去哪看"，不回答"结果应该是什么"。
  靠结构兑现 —— 只给三个窄接口（changed_surfaces / find_locator / find_route），
  **不给通用 grep**；断言/监督/finish 的判据不接源码通道。
- 源码放置：用户选了「节点存工作副本」。我推荐的是「平台提炼索引下发」
  （源码和凭据都不下节点），代价是每种技术栈一套提炼器 —— 记在 ADR 的
  「被否掉的方案」里，两者工具接口相同，将来要换是可平移的。
- 三个配套不能省：短期只读凭据（一小时、按 repo）、**git worktree**
  （多会话测不同分支，共用工作区会互相 checkout 且不报错）、**commit sha 对账**
  （分支和被测包对不上时线索是错的，比没有更慢 —— 对不上就停用并说明）。

**下一步**：P1 只做 `changed_surfaces`，判据是探索轮数/token 降幅，降不下来就停。

## 那两刀已经做掉了（c2975eb3，P-65）

- **孤儿 harness 子进程**：`PR_SET_PDEATHSIG`（Linux，实测 kill -9 节点后
  harness 5 秒内自退）+ 启动时收尸（三平台，实测清掉过一个）。
  收尸的判据是「命令行含 tke 和 session id」，不是「pid 还在」—— 防 pid 复用误杀。
- **adb 成功路径丢 stderr**：已带上；dump 第二次重试改带 `--compressed`；
  「没有输出」的文案按 INV-18 重写。

**注意**：`pgrep -f "tke serve …"` / `pkill -f` 会匹配到发起命令的那个 shell 自己，
kill 下去把自己杀了（退出码 144）。这一场又踩了两次 —— 写验证脚本时尤其容易中招。
