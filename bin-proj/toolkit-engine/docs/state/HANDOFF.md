## P1 做了什么

`src/serve/` 四个文件，每个都能单独测：

| 文件 | 职责 | 关键点 |
|---|---|---|
| `allowlist.rs` | 命令白名单 + 禁用旗标 + 宿主路径表 | INV-16 的执行点。**没有"绝对路径一律拒"的兜底**——那会把 URL/包名/输入文本全误伤；防线是"表 + 守卫" |
| `lease.rs` | 设备独占 + 目录隔离 + TTL/心跳 + **复位计划** | INV-17。复位只出计划不执行（执行在 routes），所以这层能无设备单测 |
| `exec.rs` | 子进程 + 参数注入 + 分层计时 | 全局参数**放子命令前面**（放后面撞 P-44）；`--copilot=false` 强制关（L1 零 LLM 面） |
| `routes.rs` | 9 个端点 | 鉴权走中间件而不是每个 handler 自己查——"忘记查"是这类代码最典型的洞 |

会话目录布局有个细节值得记：`logs` 放在 `workspace` **里面**。因为证据要能被下一条命令按
**相对路径**引用（`tke report logs`），而绝对路径正是我们禁掉的东西。

## 这一场最有价值的三件事

1. **守卫抓到两个真洞**：`scripts/check-serve-paths.sh` 还没写完，思路刚成形去盘点就发现
   `refresh --out` 和 `control browser-download --dir` 都是宿主路径、都不在表里——
   两个都能读写会话工作区外。**根因是"给命令加参数的人根本不会想到 serve"**，
   所以这事必须让机器盯着，不能靠人记得。已挂 pre-commit，并按 P-12 造违规现场验过它真的会红。
2. **单测逼出一个真 bug**：`acquire` 里顺手 `retain` 掉过期租约 → 设备**绕过复位**直接
   给下一个租户，正好违反刚写的 INV-17。改成过期租约照样占着设备，直到 sweep 复位完才回池
   （代价：TTL 到期后最多再等一轮清扫 15s 才回池，值得）。
3. **量了才知道**（Q-17）：进程启动 **0～1ms**，占比 <0.1%；耗时全在设备
   （起浏览器 690ms / 真打开页面 5.0s / 安卓一步 10.4s）。
   ADR-0022 D2 的重新审视触发条件**没有出现**——在有更强证据前别为性能重构成 in-process。

## P2 做了什么

`src/remote/`（客户端）+ 两条生成式 remote skill。设计目标只有一个：**同一条命令行在本地和远程表现一致**。

- 拦截在 **clap 之前**（先过本地 clap = 要求两端版本严格一致，正是要避免的耦合）
- 只有两个参数有新含义：`-d`（租哪台）、`--log`（转发 + 拉回**同一个相对路径**）
- stdout / 退出码原样透传；会话隐式建立并落盘复用
- `tke remote status|open|close|pull|devices|push`

### P2 逼出来的两件事

1. **`--log` 的语义在 P1 里是错的**。P1 把它列为禁用旗标（服务端注入落点）。
   实跑安全轨才发现：本地 `--log logs/scan` 再 `tke report logs/scan` 靠这个相对路径对上，
   远程吃掉它的话第二条命令找不着东西。改成**全局沙箱路径参数**——两边同一个相对路径。
   **教训**：判断"这个参数该不该让调用方给"，光看它的名字不够，要看**下一条命令会不会引用它**。
2. **无设备会话**。写 security remote skill 时发现 `http`/`recon` 根本不碰设备，
   却被租约模型强制租一台——用户要为没用到的设备付租金，直接违背 ADR-0022 D3 的计费模型。
   加了 `platform: "none"`：不占池、不互斥、不复位、不计设备时长。

### remote skill 是**生成**的，不是抄的

`skill/remote-delta/<名>-remote.md`（只维护差异）+ `build-remote.sh`（把本地版正文**逐字节内联**）
→ `skill/<名>-remote/`（生成物，不进 git）。publish.sh 打包前自己跑，四个包已进 manifest。
Q-18 审计：真正要分叉的只有 4 个话题（装/连、`doctor --fix`、有头登录、日志落点），做成覆盖表。

## P3 做了什么

任务层（L2）：`POST /v1/tasks` 起后台任务 → 子进程跑 `tke harness --json` / `tke security`
→ SSE/WS 看进度 → 终态释放会话 + webhook 回调。**这是"下发完就脱手、回头收报告"那条路。**

- **五态出口复活**（ADR-0009 的条款，D6/INV-3）。headless 一看到 `awaiting_input`
  就**立刻终止并回传问题原文**——继续跑下去就等于让它自己拿主意了。
- **没有 `done` 事件 = 没跑完**，退出码 0 也判 `error`：编排本该以 done 收束。
- WS 桥的是 `JsonFrontend` 的双向 NDJSON——**那协议本来就是给长连接设计的**（Electron app 在用），
  这里只是把管子从 stdio 换成 WebSocket。

### 实测逼出来的三处

1. **参数校验必须在租设备之前**：拼错的 `kind` 先撞上"没有 android 设备可租"（409），
   把"你写错了"报成"这儿没有"。
2. **失败任务要交出 stderr 尾巴**（最后 50 行）：这次挂的原因是节点没配 API key，
   不给尾巴调用方只知道"失败了"（P-46 同款）。stderr 不进事件流（它是节点日志不是协议），
   进 `detail.stderr_tail`。
3. **终局事件要进重放缓冲**：原本 `task_end` 只广播不落缓冲，于是"任务早跑完了才来订阅"
   的人只看到一片空白——而那恰恰是主场景。

## 平台对接（ADR-0023）

摸了 `TOOLKIT/bug`（测试管理平台）。**结论是 tke 侧几乎不用改**——它的 `scripts` 表注释
就写着「后续 TestRun 触发自动化跑、回填结果都从这里出」，`case_results` 已有 `bug_id`，
还有一套跑熟的长作业范式（`release.Runner`）和卡片式交互（正好接 `needs_decision`）。

用户拍板四条：平台是客户端（先直连）/ 自动化与手工 run 同一实体 /
安全是平台的第七个实体 / 设备池是平台级页面。

平台上的两个按钮直接落到已有两层：**回归回放走 L1**（零 LLM，只计设备时长）、
**AI 探索与安全扫描走 L2**（平台 key，记 token）——计费模型天然对上。

### 这一轮 tke 侧只做了两件事

1. **任务终态给 `usage`**（计费必需）：从 `Summary` 事件抽 token+model。
   **测不到时是 null 不是 0** —— 0 会被平台读成"这次没花钱"。
2. **修了 P3 的一个真 bug**：`tke security --json` 无头跑完只打一个**没有 `type` 字段**的
   结果对象，于是"没有 done 事件 = 没跑完"把**成功**的安全扫描判成了 error。
   P3 只测了失败路径才漏掉的。现在的规则对所有"一次性命令"类任务通用。

### 安全轨的用量也补了（计费的最后一块）

它不走 `Summary` 事件，所以另建了 `workflow/security/usage.rs`：把 prober / analyst
（每条 finding 一次）/ orchestrator 三处会话的 `total_usage()` 汇总，**分角色留账**——
钱花在自主探测还是对抗复核上是能指导调优的信息，合并成一个总数就再也分不开了。

三个容易漏的点，都钉了测试：
- **analyst 重试失败那一轮也要记账**（同样烧了 token，不记就是漏账）
- **交互式 orchestrator 自己那段会话也算**（否则对话式跑出来的账只有复核那一半）
- **没量到给 null 不给 0**：供应商没回 usage 时全 0，那也算没量到，宁可报不知道

交付走两条路，谁先到用谁：无头终局 JSON 的 `usage` + `findings.json` 里的同名字段。
**FakeTurn 带 token 且会被累计**，所以记账逻辑本身是无 key 端到端测过的。

### AI 改走平台网关（形状变了，ADR-0023 D6）

原本要"平台把 App 的 key 随任务交给节点"，为此给凭据做了一路防护。
用户提出更好的形状：**平台出 AI 网关**转发原生请求 + fallback，节点只调网关地址。
于是 **用户的 key 一步都不离开平台**，前面那路防护变成纵深防御而不是唯一防线；
**计量也从"节点自报"变成"网关侧权威"**（tke 仍回 usage，只作对账）。

tke 侧为此只改了一处，但这一处是必须的：`[ai].base_url` 原本硬限制在 doubao/qwen 上
并**强制换成 OpenAI 适配器**——那等于把网关这条路堵死。现在放开给所有 provider 且
**保留原生适配器**（只换端点不换协议）。
⚠️ **必须保原生**：走 OpenAI 兼容会丢 anthropic 的思考块（历史坑），而思考块是 harness
质量的来源之一。所以**平台网关要做原生透传，别把一切压成 OpenAI 格式**。

配套：`TKE_AI_*` 环境变量覆盖 `[ai]`（argv 会被 `ps aux` 看见，配置文件会落盘）；
`meta` 归账标签原样透传（任务 + 会话，设备租赁与 AI 计费共用同一条路）；stderr 尾巴脱敏。

## 埋的坑 / 下一场注意

- **P1 有意没做的三件**，别当成遗漏：`tke file` 不进白名单（`push`/`pull` 把宿主路径和设备路径
  混在同一批参数里，语义要单独设计）；TLS 交反代；`drivers::fake` 的状态是进程级注册表，
  子进程里是空的——所以接口测试用的是 `task new`/`device` 这类不碰设备的命令，
  "设备命令"那条路由 e2e 覆盖。想让 CI 也覆盖，得先让 fake 状态可落盘，**需要时再做**。
- **网络那段还没量**：本机测跑在回环上。跨机部署后要再量一次，`timing` 字段已经就位。
- **下一场 = P4（平台对接：节点注册/心跳/能力上报）或 P5（部署形态：Docker / mac 节点 /
  GitHub Action）**。两条都不依赖真机验证才能开工。
- **Q-20：任务层的 AI 端到端没跑过**。本机没有 API key，所以「真拿到 done / 出报告 /
  WS 交互式回答一个 awaiting_input」全没验。尤其 `needs_decision` 的**真实触发**——
  单测钉的是"看到 awaiting_input 就终止回传"，但真实 harness 什么时候问、问什么，
  只有真跑过才知道（问题文本要能让平台直接推给用户）。
- **跨机仍未验**：P1/P2 的实测全在本机回环上。网络那段的耗时没量过（Q-17 后半截），
  `timing` 字段已经就位，量它不用改代码。按本项目的规矩，**跨机远程要等用户实跑才算数**。
- **remote skill 没被真的 coding agent 用过**：生成出来了、命令实跑过，
  但"另一台零环境机器上的 Claude Code 照着它跑完一次检查"这件事还没发生——
  那才是 P2 真正的验收（`remote-api.md` §8 的 P2 行写的就是这个）。
- `--log` 只收相对路径；没有后台心跳（改成每条命令前续租一次）——都是有意的，见 §12。
