### tke 侧这一场的两刀

**源码沙盒 P1**（`dc6fd20e`）——细节看 ADR-0025 末尾的「P1 落地记录」。
三件事值得记住：

1. **工具形态而不是上下文注入**。把变更面直接铺进上下文的成本**每次探索都付**，
   而 AI 未必用得上；做成工具 + 开场一句话提示，成本是那句话。
2. **只在配了源码时才暴露**。让 AI 看见一个"调了也没用"的工具，只换来一次白跑的往返。
3. **红线（INV-19）不能靠提示词**。它在结构里：`Surface` 没有内容字段，
   想泄题得先改结构体；无设备回归直接断言 `!conv.contains("<template>")`。

**security 目标对话式**（`292f6a28`）——改法是**零破坏地多一条路**：
`--json` 给了 URL 仍走一次性 JSON（Electron/CI 现有调用方拿的就是那份），
没给 URL 才进对话外壳（那种情况从前本来就只会报错）。

1. **守卫比我先看见问题**：`check-serve-paths.sh` 当场拦下 `--tree` ——

### 2026-08-30 CLI 文案（INV-18 第二轮）

用户拿 zellij 的 `-h` 对照，指了三处：`--help` 要清晰不废话且有颜色区分、
打错命令不该被科普 tke 的设计、中断提示不该是一大段。

改完之后 INV-18 多了一节「这条也管 `--help`」——**下次加命令照那几条写**：

- 形照 clap：`USAGE` 在最前，一条一行、动词开头
- 描述里不写背景，不写内部编号（`（ADR-0025）` 对敲命令的人没有意义）
- 子命令的 `--help` 里不重复分类前缀（`[工具]`）——他已经敲了那条命令
- 例子放 doc comment 的**第二段**，塞在标题那行会跟 clap 的 `Usage:` 抢地方
- 颜色只三种（段标题 / 命令名 / 次要说明）

**顺带发现**：`--help` 漏列了 5 个命令（http / recon / sandbox / serve / remote）——
因为顶层 help 是**手写**的（`cli/help.rs`），加命令时不会自动出现在那儿。
加命令记得同时改它。
