# tke security 报告规范（spec）

`tke security` 出两级产物。本规范定它们的**段落、评级、品牌、机器可读伴生文件**。
实现技法照抄 `src/workflow/report.rs`（自包含 HTML），只是段落不同。关联 ADR-0019。

## 通用技法（照抄 report.rs，不重造）

- **单文件自包含**：CSS 全内联，无 CDN，离线/内网/断网都能开。
- **证据 base64 内嵌**：截图/关键响应片段内嵌前先缩放（见 report.rs `EMBED_MAX_WIDTH`），
  大响应体只给文件链接不内嵌。
- **亮暗自适应**：`prefers-color-scheme`，调色板沿用参考报告：
  `--red:#ff5c5c 高危 / --amber:#ffb454 中危 / --blue:#5cc0ff 信息·链接 / --green:#4ec9a5 通过·修复 / --mut 灰:查不了`。
- **转义**：所有注入到 HTML 的目标值走 `esc()`（响应体里可能带 `<script>`，绝不能原样进 DOM）。
- **凭据脱敏**：报告里的 token/密码/密钥一律 `••••••`（承 P-45，复用 `utils/redact.rs`）。

## 品牌留痕（参考报告缺的就是这个）

- **header** 左上角内嵌 `assets/logo/toolkit_logo.png`（base64）+ 产品名。
- **footer** 水印：`Generated by Toolkit Studio · tke security · <version> · <日期>`。
- **favicon**：内嵌 emoji 或 logo，标签页可辨。

## 严重度分级与总评

| 级别 | 色 | 判据（示例） |
|---|---|---|
| 高危 Critical | 红 | 零凭据可读敏感数据 / 可注入 / 认证绕过 |
| 中危 Medium | 琥珀 | 需一定条件的越权 / 信息泄露 / 配置缺陷 |
| 低危 Low | 蓝 | 缺安全头 / 版本暴露 / introspection 开着 |
| 信息 Info | 灰 | 指纹、可改进项，非漏洞 |

**总评**：取最高危级 → `clean / 低 / 中 / 高`，映射 `outcome` 与退出码（ADR-0019 第 5 条）。

## 全局报告 `security-report.html`

面向「整体安全水平」，一屏读懂。段落顺序：

1. **头**：目标 + 日期 + tke 版本 + **总体评级 badge** + **本次强度 badge**（passive/safe/aggressive/red-team）+ 品牌 logo。
2. **一句话总结**：这个产品当前安全水平的一句话（琥珀卡片，同参考报告 `.tldr`）。
3. **安全水平总评**：各维度小结（认证鉴权 / 数据暴露 / 注入 / 传输 / 配置）→ 每维一句话 + 色点。
4. **发现清单**：表格（严重度 badge / 标题 / 类别 / **链接到对应单漏洞报告**）。按严重度降序。
5. **已检查·未命中**（INV-9 失败可见）：列出跑过但没打中的检查项，让人知道「测了没事」而非「没测」。
6. **方法与边界**：**本次强度模式**（passive/safe/aggressive/red-team）+ 聚焦面（--focus）、
   测试信息层级（无信息/API文档/源码）、该模式下做了什么没做什么（照 ADR-0019 阶梯表）、
   覆盖范围与已知盲区。red-team 若触发过不可逆动作确认，在此列明哪几次、确认结果。

## 单漏洞报告 `vuln-<slug>.html`

每个**过了 analyst 闸门**的确认漏洞一份。段落照参考报告并补齐：

1. **头**：严重度 badge + 一句话标题 + 目标/日期/组件 meta + 品牌。
2. **一句话**：这个漏洞是什么、影响谁（琥珀卡片）。
3. **多方归因**（参考报告的表）：`主因 / 机制 / 加重 / 建模`——不止「哪错了」，还有「为何会这样」。
4. **复现**（命令块，零凭据或声明凭据）：可直接粘贴执行的最小步骤 + 关键响应（脱敏）。
5. **暴露的数据 / 影响**：具体暴露了什么，举一两条真实样例（脱敏）。
6. **风险**：对业务的实际后果（竞争/合规/攻击面扩大…）。
7. **修复建议**：编号步骤（参考报告 `ol.fix` 绿色序号），推荐解在前，止血在后。
8. **证据**：req/resp 片段、截图（base64 内嵌，可点击展开，同 report.rs）。
9. **footer**：品牌水印 + 免责（只读、未破坏、数据敏感勿外传）。

**软硬证据分字段**（INV-13 / ADR-0009 第 4 条）：报告须标明该判定是
「已黑盒复现（硬）」还是「疑似·待复现（软）」——软的不进独立报告，只在全局清单里标疑似。

## 报告材料库（agent 可组合的区块）

报告不是死模板，而是 agent 从一套**区块**里挑选拼装。每个区块有固定语义和渲染类，
agent 只决定「放哪些、填什么」，样式由模板保证。按用途分五类。

**排序铁律**：评级 / 基础信息 / 一句话总结**永远在最前**——读者三秒内要拿到「多严重、大概什么事」。
后面才是图表、详情、复现。

### A. 概览类（必在最前）
| 区块 | 用途 | 关键规则 |
|---|---|---|
| `scoreboard` 计分板 | 风险等级 grade + KPI 数字条（发现数/最高 CVSS/端点数/用时） | 一屏第一眼，数字不超过 4 个 |
| `donut` 严重度环形图 | 五级分布，中心放总数 | 零项在图例里灰化，不省略 |
| `tldr` 一句话总结 | 通俗一句讲清「什么事+多严重+该干嘛」 | 不写术语，给非技术读者看 |
| `runmeta` 运行元信息 chips | 强度模式 / 信息层级 / 聚焦面 / 日期 / 版本 | 强度 chip 必出（INV-15） |

### B. 图表类（可视化，择一或多）
| 区块 | 用途 |
|---|---|
| `donut` 环形分布 | 严重度构成（见 A） |
| `bar` 分类柱状 | 按类别（auth/injection/…）看分布 |
| `heatmap` 风险矩阵 | 可能性 × 影响 的 5×5 网格，标出每个 finding 落点——安全报告标配 |
| `attackpath` 攻击路径 | 把「侦察→越权→取数」串成带箭头的步骤链，讲清怎么打穿 |
| `timeline` 时序 | 探测请求随时间分布 / 评估里程碑 |

### C. 文字卡片 / 列表类
| 区块 | 用途 | 关键规则 |
|---|---|---|
| `callout` 重点卡 | **大字**通俗结论 + **小字**补充细节 | 一个卡只讲一件事；大字是人会记住的那句 |
| `attribution` 归因表 | 主因 / 机制 / 加重 / 建模 | 不止「哪错」，还有「为何这样」 |
| `dims` 维度总评 | 认证/数据/注入/传输/配置，每维一句 + 色点 + 级别药丸 | 通过项也列（对照） |
| `checklist` 已检查·未命中 | 跑过但没命中的项 | INV-9：让人知道「测了没事」而非「漏测」 |
| `exposed` 暴露数据列表 | 具体暴露了什么，举一两条脱敏样例 | 样例必脱敏 |
| `fixsteps` 修复步骤 | 编号步骤，推荐解在前、止血在后 | —— |

### D. 可复制执行类（copy-paste，用户重点）
| 区块 | 用途 | 关键规则 |
|---|---|---|
| `cmd` 命令块 | 单条可执行复现：curl / wget / httpie… | **右上角复制按钮**；`<pre>` 内**只放可直接跑的行**（# 注释可留），实测结果放块外 caption |
| `script` 脚本块 | 整段可执行：bash / python / sh | 同上带复制；顶部标语言；可跑通、幂等、只读/受控 |
| `reqresp` 请求响应对照 | 原始 HTTP request → response 并排/上下 | 脱敏；这是「硬证据」的呈现 |
| `diff` 配置前后 | 修复的 before/after（nginx/headers…） | 绿加红减 |

复制块的纪律：**复制出来的东西必须能直接粘进终端跑**——所以注释用 `#`、把「实测输出/预期结果」这类
非可执行文字移到块外的说明行，不混进可复制区。

### E. 证据与语义标记
| 区块 | 用途 |
|---|---|
| `shot` 截图 | base64 内嵌、点击展开（同 report.rs），手机竖图限高 |
| `evi` 证据行 | 指向 `evidence/` 下的 req/resp/日志文件 + 判定依据一句 |
| `pill` 语义药丸 | 严重度 / CVSS / CWE / `已黑盒复现`(硬) / `疑似·待复现`(软) / 通过 |
| `compliance` 合规映射 | 把 finding 映到 OWASP Top 10 / CWE / 合规条款 |

**软硬证据必分**（INV-13）：`已黑盒复现` 和 `疑似·待复现` 用不同药丸，软的不进独立漏洞报告。

### 组合约定
- **全局报告** = A 全上 + B 选图 + C(dims/checklist) + 发现清单（链到单漏洞）+ 方法与边界。
- **单漏洞报告** = A(tldr) + C(callout/attribution) + D(cmd/script/reqresp) + C(fixsteps) + E(shot/evi/compliance)。
- agent 只从这份库里选，**不即兴造新样式**——保证跨报告观感一致、可回归。

## 机器可读伴生 `findings.json`（给 --json / Electron）

每个 finding 一条，字段至少：

```jsonc
{
  "id": "vuln-open-dataset",          // 与 vuln-<slug>.html 对应
  "severity": "critical",             // critical|medium|low|info
  "title": "…",
  "category": "data-exposure",        // data-exposure|injection|auth|transport|config
  "confirmed": true,                  // 硬证据=true；软判断=false（不出独立报告）
  "repro": "GET dv01o3wh.api.sanity.io/…",
  "evidence": ["evidence/step_003_req.txt", "evidence/step_003_resp.txt"],
  "report": "vuln-open-dataset.html"
}
```

顶层再给 `outcome`（clean/findings/needs_decision/blocked/error）、`score`（总评级）、
`mode`（passive/safe/aggressive/red-team）、`focus`（数组或 null）。
Electron/无头 UI 读这份即可渲染，不必解析 HTML。
