查这次代码改动碰到了**哪些界面**，按改动规模排序。

**什么时候用**：探索一开始、你还不知道该往哪儿找的时候，先调它一次。
它把你的注意力直接放到"这次真的改过"的那几个界面上，省掉一层层点着找的过程。

**它给你什么**：界面名、属于哪一类（activity / page / view_controller …）、
相关文件路径、改动了多少行。

**它不给你什么**：任何一行代码。所以你**无法**、也**不应该**从它推断
"点了之后应该显示什么" —— 那是用例说了算、由你在真机上看到的东西说了算。
用它来决定**去哪里看**，不要用它来决定**看到的对不对**。

一次探索调一次就够了，它不会变。
