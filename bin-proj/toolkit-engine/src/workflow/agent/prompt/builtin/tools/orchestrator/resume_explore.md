断点续探（修复原语）：保留脚本前 `keep_steps` 步不动，探索 agent 从**设备当前页面**出发把 `goal` 走完，脚本=前缀+新尾巴写回（失败不写回）。**不做验证**——修完你要再 replay_tks 确认。

修复由**你**决策，标准流程：
1. replay_tks 拿失败报告（失败步/原因/失败现场页面摘要）；
2. 判断：定位问题/流程改版 → 本工具续探（keep_steps 通常=失败步-1；全跑通但终点不符=全部步数）；**起始态没对齐**（登录态/所在页不对）→ 先 explore 导航回起始状态再重放，不要续探；拿不准 → 问用户；
3. note 里把失败原因+用户给的纠偏写清——续探 explorer 看不到你的对话，全靠 note；
4. 写回后 replay_tks 验证，通过才算修好。

前提：设备停在失败现场（刚 replay 失败后直接调最准）；中途做过别的设备操作就先想清楚现场还在不在。
