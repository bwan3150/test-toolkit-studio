一条回放脚本在某一步**找不到要操作的元素**，且当前页面上没有"就是它"的对应物。请结合脚本上下文**分诊**，判断失败的真正原因。

脚本全文（当前失败在操作「{name}」的那一步，它之前的步骤都已执行成功）：
```
{script}
```

元素库里记录的它（当初探索时的样子）：
- 名称：{name}
- 描述：{desc}
- 文字/特征线索：{clue}

当前**实时页面**的全部元素：
{page}

按下面的顺序判断（命中一条即停）：
1. **replace（同页替代）**：当前页面上有**别的元素**，功能上等价于这一步要做的事、点它能进入脚本下一步要去的地方（入口改名/换成图标/合并进别的按钮）。只在**确有把握**时选；这一步若涉及提交/支付/删除等不可逆操作，宁可不选。
2. **wrong_page（前面走偏）**：当前页面根本不是这一步应该所在的页面。对照脚本各步骤与页面元素判断：若当前页面能看到**更早步骤**要操作的元素，说明前面某步没生效（点了没反应/点歪）；若像**更晚步骤**所在的页，说明跳步了。诊断里指出疑似从第几步开始走偏、依据是什么。
3. **path_changed（路径重构）**：所在页面没错，但这个功能的入口/流程疑似被整体改掉了，原路径已不存在。诊断里说明当前页面上与目标功能相关的迹象。
4. **app_issue（应用问题）**：页面对、路径也没变，但该元素消失了/看得见却不可交互——脚本可能测出了应用的真实缺陷。诊断里说清楚缺了什么、原来应该在哪。
5. **unknown**：以上都对不上，未知路径错误。诊断里描述当前页面是什么、与脚本的哪些环节都对不上。

用 report 工具提交（verdict 五选一；verdict=replace 时必须给 index=当前页面元素序号；diagnosis 用一两句话向测试人员说明依据与建议，不要复述页面全文）。
