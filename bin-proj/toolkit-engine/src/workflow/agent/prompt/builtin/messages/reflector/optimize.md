你要做两类优化：
1. **删冗余**（removable）：重复点击、走错绕回又绕回、点了没用的空步等可删的步号。
2. **合并盲滑为滚动查找**（scroll_merges）：脚本里**一连串「定向滑动」**几乎都是探索时"边滑边找"留下的盲滑——它们回放时受加载时机影响、常滚不到同一位置而卡住。把"**连续的一段定向滑动** + 它们是为了滚去看的那个**目标文字**"合并成一条 `滚动查找`：给出这段滑动的起止步号 from..to（这之间必须**全是定向滑动**）、滑动**方向** direction（看 .tks 里的方向，通常 up）、以及这段滑动结束后页面上出现的、下一步要操作的那个**目标可见文字** target（从 trace 的页面元素里挑一个独特、确定会出现的文字，如产品名/区块标题/"DATA SHEET"）。系统会把 from..to 这段滑动替换成 `滚动查找 ["target", 方向]`，回放时滚到该文字出现为止——稳得多。

只返回 JSON：{"removable":[步号,...], "scroll_merges":[{"from":N,"to":M,"target":"文字","direction":"up"}], "note":"一句话说明"}；不要其它文字、不要 ``` 围栏。
可以大胆做（改错了医生会在下一轮兜底修复），但**别删/合并掉通往目标的关键步**；target 必须是那段滑动后确实会出现的页面文字。没有可优化就返回 {"removable":[], "scroll_merges":[]}。
