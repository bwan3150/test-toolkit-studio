# .tks 指令语法（`tke steps` 用的就是这个）

格式：`命令 [参数, 参数]`，无参命令写裸命令（`返回`、`隐藏键盘`）。
一次 `tke steps` 可以传多条，按顺序执行。

## 参数写法

| 类型 | 写法 | 说明 |
|---|---|---|
| 坐标 | `{640, 380}` | **ui-check 主要用这个**，截图像素坐标 |
| 元素 | `{登录按钮}` | 需要元素库（.tklib），ui-check 一般不用 |
| 文本 | `"要输入的字"` | 双引号 |
| 时长 | `2s` / `1500ms` | 带单位 |
| 方向 | `上` `下` `左` `右` | |
| 存在性 | `存在` / `不存在` | 断言条件 |

## 指令表

### 打开 / 关闭

```
启动 ["https://example.com"]                  # web
启动 ["com.example.app", ".MainActivity"]     # 安卓（包名+Activity，用 tke app focus 查）
启动 ["com.example.BundleID"]                 # iOS
关闭 ["com.example.app"]                      # 关 App；web 传空即销毁会话
切换 ["2"]                                    # web 切到第 2 个标签页
切换 ["https://..."]                          # web 新标签打开
切换 ["com.example.app"]                      # 移动端把 App 切到前台
```

### 点击 / 输入

```
点击 [{640, 380}]
按压 [{640, 380}, 1000]          # 长按 1 秒
悬停 [{640, 380}]                # web 独有：鼠标移上去触发 hover 菜单
输入 [{640, 380}, "文本"]         # 先点这个位置再输入
清理                             # 清空当前输入框
隐藏键盘
按键 ["KEYCODE_ENTER"]           # 安卓按键事件
返回
```

### 滑动 / 滚动

```
滑动 [{640, 800}, {640, 300}]           # 从一点滑到另一点
滑动 [{640, 800}, {640, 300}, 500]      # 带时长（毫秒）
定向滑动 [{640, 450}, 上, 400]           # 从某点向上滑 400
滚动查找 [{目标元素}]                     # 边滚边找（需要元素库）
```

### 等待 / 断言

```
等待 [2s]
断言 [{某元素}, 存在]                 # 需要元素库
断言 [{某元素}, 不存在]
断言 [{提示}, 存在, 15s]              # ★ 重试断言：15 秒内反复重判，一成立就通过
断言页面 ["起始页"]                    # 按页面特征投票（需要元素库里的 pages）
```

**等异步结果就用重试断言**（第三个参数）——固定 `等待 [N s]` 快了假失败、慢了浪费时间。
后台下发、跨设备同步、请求返回这类场景必用。

> ⚠️ 断言的目标**必须是元素**（`{名字}`），不能写坐标——它需要元素库。
> ui-check 场景不建元素库，所以**判断结果靠你自己 `fetch` 后读**，
> 而不是写断言。断言主要服务于 `tke harness` 产出的可回放脚本。

## ui-check 场景实际会用到的

绝大多数检查用这几条就够：

```bash
tke -d web steps \
  '启动 ["http://localhost:3000/x"]' \
  '点击 [{640, 380}]' \
  '输入 [{603, 112}, "测试内容"]' \
  '等待 [1s]' \
  --log .tke-check/
```

然后 `tke -d web fetch` 看页面变成什么样，自己判断成没成。
