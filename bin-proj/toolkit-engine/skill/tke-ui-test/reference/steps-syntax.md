# `tke steps` 指令语法

格式：`命令 [参数, 参数]`，无参命令写裸命令（`返回`、`隐藏键盘`）。
一次 `tke steps` 可以传多条，按顺序执行。

> 这套指令与 `.tks` 脚本同源，但**你只把它当 `steps` 的命令行参数用**——
> 这个 skill 不写 `.tks` 文件、不建元素库。产出可回放脚本是 `tke harness` 的活，
> 跟这个 skill 是两回事。

## 参数写法

| 类型 | 写法 | 说明 |
|---|---|---|
| 坐标 | `{640, 380}` | **tke-ui-test 主要用这个**，截图像素坐标 |
| 元素 | `{登录按钮}` | 需要元素库（.tklib），tke-ui-test 一般不用 |
| 文本 | `"要输入的字"` | 双引号 |
| 时长 | `2s` / `1500ms` | 带单位 |
| 方向 | `上` `下` `左` `右` | |
| 存在性 | `存在` / `不存在` | 断言条件 |

## 哪些指令哪些平台有

跨端脚本别写上不支持的动作——**不支持的会明确报错**（不会静默跳过，所以不会假装成功）。
认不出的按键同理：以前是"报成功但什么都没做"，人会以为焦点已经移走、接着往下写，
错在后面几步才暴露。

| 指令 | 安卓 | iOS | 网页 |
|---|:--:|:--:|:--:|
| 点击 / 按压 / 滑动 / 定向滑动 / 输入 / 清理 | ✅ | ✅ | ✅ |
| 启动 / 关闭 / 切换 | ✅ | ✅ | ✅ |
| 等待 / 断言 / 滚动查找 | ✅ | ✅ | ✅ |
| 返回 | ✅ | ✅ 手势模拟 | ✅ 浏览器后退 |
| 按键 | ✅ 全部 keycode | ⚠️ 只有 ENTER/BACK | ⚠️ ENTER/TAB/ESC/BACKSPACE + 单个字符 |
| 隐藏键盘 | ✅ | ✅ | — 无软键盘 |
| **悬停** | ❌ | ❌ | ✅ |
| **选择**（原生下拉） | ❌ | ❌ | ✅ |
| **确认/取消对话框、对话框输入** | ❌ | ❌ | ✅ |

**同名不同义**，跨端时最容易想当然：

- `启动`：安卓要**包名+Activity**（`tke app focus` 查，别猜）/ iOS 要 **BundleID** / 网页是 **URL**
- `关闭`：移动端是杀 App，设备还在；**网页是销毁整个会话**——浏览器、driver、登录态一起没，
  要人工登录的流程中途千万别关（见踩坑册 C-6）
- `切换`：移动端把 App 切到前台 / 网页是切标签页（`切换 ["2"]`）或新开标签（`切换 ["URL"]`）
- `返回`：安卓 BACK 键 / iOS 是**左边缘右滑手势**（某些 App 里不生效）/ 网页是 history.back()

坐标一律是**截图像素**，三端统一，你不用管换算。

## 指令表

### 打开 / 关闭

```
启动 ["https://example.com"]                  # web
启动 ["com.example.app", ".MainActivity"]     # 安卓（包名+Activity，用 tke app focus 查）
启动 ["com.example.BundleID"]                 # iOS
关闭 ["com.example.app"]                      # 关 App；web 传空即销毁会话
切换 ["2"]                                    # web 切到第 2 个标签页
切换 ["https://..."]                          # web 新标签打开
切换 ["com.example.app"]                      # 移动端把 App 切到前台
```

### 原生对话框（alert / confirm / prompt，web 独有）

```
确认对话框                       # 点「确定」
取消对话框                       # 点「取消」
对话框输入 ["张三"]              # prompt 里填字**并确定**
```

这三种框是**浏览器画的**，不在 DOM 里——`fetch` 一个字都采不到、截图也拍不到。
弹出来时 tke 会在那一步的结果里报 `dialog: "确定删除？"`，**并且挡住后面所有操作**
（下一步会直接报错让你先处理掉）。别去 fetch 找它，直接用上面三条。

### 点击 / 输入

```
点击 ["保存"]                    # 首选：按文字
点击 [{640, 380}]               # 兜底：坐标
按压 [{640, 380}, 1000]          # 长按 1 秒
悬停 ["菜单"]                    # web 独有：鼠标移上去触发 hover 菜单
选择 ["模式", "日间模式"]         # web 独有：原生 <select> 只能用它——展开后的
                                 # option 由浏览器绘制、DOM 里不可见，点是点不到的
输入 ["搜索框", "关键词"]         # 先点这个元素再输入
输入 [{640, 380}, "文本"]         # 坐标形式
清理                             # 清空当前输入框
隐藏键盘
按键 ["KEYCODE_ENTER"]           # 安卓按键事件
返回
```

### 滑动 / 滚动

```
滑动 [{640, 800}, {640, 300}]           # 从一点滑到另一点
滑动 [{640, 800}, {640, 300}, 500]      # 带时长（毫秒）
定向滑动 [{640, 450}, 上, 400]           # 从某点向上滑 400
滚动查找 ["目标文字", 上]                 # ★ 边滚边找，纯文字、不需要元素库
```

> ★ **`滚动查找` 是这个 skill 的关键指令，别跳过**：定位只看得见**当前视口内**的元素，
> 目标在折叠下方时 `点击 ["文字"]` 会直接失败（还要白等满 ~6 秒重试）。
> 先 `滚动查找 ["文字", 上]` 把它带进视口，再点就稳了：
>
> ```
> 滚动查找 ["Memory safety", 上]    # 向下滚动去找（"上"=手指上滑=看更下面的内容）
> 点击 ["Memory safety"]            # 滚到了就能直接点
> ```
>
> 它每滚一步都重新识别（含 OCR），滚到底/到顶会自动停，不必猜滚几次。

### 等待 / 断言

```
等待 [2s]
断言 [{某元素}, 存在]                 # 需要元素库
断言 [{某元素}, 不存在]
断言 [{提示}, 存在, 15s]              # ★ 重试断言：15 秒内反复重判，一成立就通过
断言页面 ["起始页"]                    # 按页面特征投票（需要元素库里的 pages）
```

> ⚠️ **断言在这个 skill 里基本用不上**：它的目标必须是元素（`{名字}`）、不能写坐标，
> 也就是**需要元素库**——而这个 skill 不建元素库。断言主要服务于 `tke harness` 产出的可回放脚本。
>
> **等异步结果（后台下发、跨设备同步、请求返回）用 `fetch --wait-text`**：
> `tke -d X fetch --wait-text "名字" --timeout 30 && echo 出现了 || echo 没出现`
> ——出现即刻返回、超时非零退出。**别自己写 shell 轮询**（忘超时/忘判命中，见 C-1/C-3）。
> 固定 `等待 [N s]` 快了假失败、慢了白等。
>
> 一句话：**判断结果靠你自己 `fetch` 后读**，不写断言。

## tke-ui-test 场景实际会用到的

绝大多数检查用这几条就够：

```bash
tke -d web steps \
  '启动 ["http://localhost:3000/x"]' \
  '点击 ["保存"]                    # 首选：按文字
点击 [{640, 380}]               # 兜底：坐标' \
  '输入 [{603, 112}, "测试内容"]' \
  '等待 [1s]' \
  --log ~/.tke/logs/<任务简称>/
```

然后 `tke -d web fetch` 看页面变成什么样，自己判断成没成。
